## 목적

DRATSN은 클라우드 네이티브 환경에서 TSN 토폴로지를 인식해 vPLC 자원을 스케줄링한다. Isaac Sim은 DRATSN 자체 기능을 구현하는 도구가 아니라, 스케줄링 결과에 따른 제어 품질 차이를 청중이 직관적으로 확인하도록 시각화하는 역할을 맡는다.

비교 대상은 다음 세 가지다.

- 물리 PLC
- 일반 Kubernetes vPLC
- DRATSN 기반 vPLC

## 선정한 공장 도메인

첫 번째 셀은 **컨베이어 추종 픽앤플레이스 셀**로 구성한다.

기본 동작은 다음과 같다.

1. 제품이 컨베이어를 따라 이동한다.
2. 센서가 제품의 위치를 감지한다.
3. 로봇이 제품의 이동 위치를 추정한다.
4. 로봇이 제품을 집어 지정 위치 또는 팔레트에 배치한다.
5. 성공 여부와 처리시간을 기록한다.

이 도메인을 선택한 이유는 다음과 같다.

- 별도의 제조공정 지식 없이 동작을 이해할 수 있다.
- 지연과 지터가 커졌을 때 제품 놓침, 급정지, 처리량 감소가 화면에 명확히 나타난다.
- 자동차 차체에 문을 설치하는 셀보다 전용 3D 에셋과 정밀한 조립 설정이 적게 필요하다.
- 동일 셀 복제와 후속 공정 추가가 쉽다.

베어링 압입 셀은 산업적 개연성은 높지만 공정 설명이 추가로 필요하고, 제어 차이가 힘-변위 그래프 중심으로 나타나므로 첫 시각화 도메인에서는 제외한다.

## 구현 기반

제로부터 제작하지 않고 NVIDIA 공식 예제와 에셋을 재사용한다.

### 우선 검증할 기반

- NVIDIA UR10 팔레타이징 예제
  - 컨베이어, UR10 로봇, 그리퍼, 상자, 팔레트와 기본 동작을 제공한다.
  - 현재 목표와 가장 가까운 완성 예제다.
  - 예제의 합성데이터 생성 기능은 사용하지 않는다.
  - 제어부에서 사용하는 Cortex는 Isaac Sim 6.0에서 폐기 예정이므로 최종 제어부와 분리한다.

### 대체 기반

UR10 팔레타이징 예제가 gpu-spark2에서 동작하지 않으면 다음을 조합한다.

- Isaac Sim 6.0 UR10e 픽앤플레이스 예제
- 2F-140 그리퍼 기본 에셋
- Conveyor Belt Utility와 기본 컨베이어 조각

### 공장 배경

초기에는 장면을 가볍게 유지한다.

- NVIDIA Industrial Assets Pack의 안전펜스, 상자, 팔레트, 선반 사용
- 바닥, 작업 구역 표시, 조명 추가
- 대형 Warehouse Assets Pack 전체 적용은 초기 기능 검증 후 결정
- 공장 배경은 별도 USD 레이어로 분리하여 제어 실험에 영향을 주지 않게 구성

## 초기 씬 구성요소

- 직선 컨베이어 1개
- UR10 또는 UR10e 로봇 1대
- 평행 그리퍼 1개
- 단순한 상자형 제품 여러 개
- 제품 감지 센서 1개
- 제품 배치 위치 또는 팔레트 1개
- 안전펜스와 작업 구역 표시
- 물리 PLC, 일반 vPLC, DRATSN 중 현재 제어 방식을 표시하는 화면 요소
- 지연시간, 지터, 성공·실패, 처리량을 보여주는 화면 요소

## 씬 저장 구조

씬과 코드는 gpu-spark2의 영구 볼륨에 저장하고 컨테이너에 마운트한다.

```text
/home/netai/isaac-sim/projects/dratsn_factory/
├── scene/
│   ├── cell_base.usda
│   └── factory_background.usda
├── assets/
├── scripts/
├── scenarios/
└── data/
```

- `cell_base.usda`: 로봇, 컨베이어, 센서와 제품
- `factory_background.usda`: 펜스, 선반, 조명 등 시각 요소
- `scripts`: 시뮬레이션과 제어 연동 코드
- `scenarios`: 정상, 지연, 장애 등 실험 조건
- `data`: 원본 측정값과 결과

USD 에셋 참조는 상대경로를 사용한다. nerdctl과 Kubernetes에서는 동일한 프로젝트 디렉터리를 각각 바인드 마운트 또는 PVC/hostPath로 연결한다.

## 추가 논의가 필요한 사항

### 제어 책임 범위

- vPLC가 1ms마다 위치·속도 목표를 직접 계산할지
- 로봇 내부 제어기는 궤적을 수행하고 vPLC는 상위 명령만 담당할지
- 초고속 서보 내부 루프와 vPLC 외부 제어 루프의 경계를 어디에 둘지

### 지연과 지터 주입 방식

- Linux `netem`으로 실제 패킷에 지연·지터를 적용하는 방식
- 시뮬레이션 내부에서 정해진 확률분포에 따라 지연값을 주입하는 방식
- 실제 측정 로그를 재생하는 방식
- 위 방식을 결합하는 방식

연구실에 TSN 스위치와 TSN NIC가 없으므로, 실제 TSN 성능 검증과 모사 실험을 구분해서 설명해야 한다.

### 비교 시나리오와 판정 기준

- 정상 스케줄링
- 불리한 토폴로지 또는 원격 노드 배치
- CPU·네트워크 부하
- vPLC 재시작 또는 재배치
- 셀 확장
- 집기 성공률, 데드라인 초과율, 지터, 처리량, 복구시간의 기준값

### 화면 표현

- 세 제어 방식을 동일 씬에서 순차 실행할지
- 동일 셀 세 개를 나란히 배치해 동시에 보여줄지
- 지연으로 인한 제품 놓침과 로봇 정지를 어느 수준까지 물리적으로 표현할지
